# SCUM Dedicated Server — Docker Compose (Wine stable + DepotDownloader)

This project runs the Windows-only SCUM Dedicated Server (Steam AppID `3792580`) in a Linux AMD64 Debian Bookworm container using WineHQ stable. It deliberately downloads the Windows build through DepotDownloader — it does not include or invoke SteamCMD.

## Requirements

- Linux AMD64 host, Docker Engine and Docker Compose
- Host account `ubuntu` with UID:GID `1000:1000`
- At least 16 GiB RAM recommended (8 GiB is the bare minimum); 30+ GiB free disk
- Public firewall/security-group/NAT allows the ports below

## Install and start

```bash
cd /home/ubuntu/workspace/scum-server-docker
cp .env.example .env
mkdir -p data
sudo chown -R 1000:1000 data
docker compose build --pull
docker compose up -d
docker compose logs -f scum-server
```

On first start the image initializes a persistent Wine prefix and downloads SCUM to `data/server`; this can take several minutes. Configuration generated by the game persists in:

```text
data/server/SCUM/Saved/Config/WindowsServer/
data/server/SCUM/Saved/SaveFiles/
```

Stop the server before manually editing game configuration or backing up the SQLite world database (including its `-wal` and `-shm` files).

## Persistent data and ownership

Only `./data` is mounted from the host:

```text
data/
├── depotdownloader/  # DepotDownloader state/cache
├── server/           # SCUM installed files, logs, config and saves
└── wine/             # persistent 64-bit Wine prefix
```

The entrypoint makes this directory owned by the configured `PUID:PGID` (default `1000:1000`, the host `ubuntu` account), then launches Wine as that unprivileged user.

## Ports

Defaults are exposed by Compose as UDP:

| Purpose | Port |
|---|---:|
| Game | 7777 |
| Raw game socket | 7778 |
| Game/Steam connection | 7779 |
| Explicit query | 27015 |

Open/forward all four UDP ports. `GAME_PORT_PLUS_1` and `GAME_PORT_PLUS_2` in `.env` must always equal `GAME_PORT+1` and `GAME_PORT+2`. Avoid the Steam-reserved query range `27020-27050`.

For UFW:

```bash
sudo ufw allow 7777:7779/udp
sudo ufw allow 27015/udp
```

A remote UDP scanner cannot reliably prove an application is healthy because UDP has no connection handshake. Verify externally using Steam's server browser / SCUM direct connect to `PUBLIC_IP:7779`, after confirming local published sockets with:

```bash
docker compose exec scum-server ss -lunp
docker compose ps
docker compose logs --tail=200 scum-server
```

## Configuration

Copy `.env.example` to `.env` and adjust server identity, ports, player limit, and update policy. `ADDITIONAL_FLAGS=-nobattleye` is the default because BattleEye is generally incompatible with Wine/container deployments. `LOG_WEBHOOK_URL` is optional and accepts a Discord-compatible webhook; do not commit `.env` if it contains a webhook URL or password.

Useful commands:

```bash
docker compose restart
docker compose down
docker compose up -d
docker compose logs -f --tail=200 scum-server
```

## Troubleshooting

- Wine errors at startup: this image follows the `melle2/scum-ds` runtime directly (`melle2/wine-steamcmd-ubuntu:24.04-3`) while retaining DepotDownloader for game download. Its persistent prefix is initialized with the same sequence: remove `winebth`, then install `vcrun2017`, `d3dcompiler_47`, and native `crypt32` through Winetricks/Xvfb. On image upgrade it reruns the provisioner automatically. If provisioning is interrupted, stop the service, remove `data/wine/.scum-wine-provisioned-v*`, then start it again. To recreate the entire prefix, stop SCUM and remove `data/wine`.
- **SCUM multiplayer integrity guard:** if SCUM logs `DllIntegrityCompromised` / `0x800B0100`, it disables multiplayer before binding game sockets. This project applies the upstream melle2 Wine initialization pattern before declaring that outcome; it does not patch/bypass the guard.
- DepotDownloader error / missing executable: logs must show it ran with `-app 3792580 -os windows -osarch 64`; remove only incomplete files in `data/server` and retry. The entrypoint uses DepotDownloader, never SteamCMD.
- Not visible in the browser: ensure every listed UDP port is allowed by host firewall, cloud security group, and upstream router/NAT, then connect to `PUBLIC_IP:7779`.
- Database backup: stop SCUM first, then archive `data/server/SCUM/Saved/SaveFiles/` as a unit.
